# Product docs

What the whole product is: the concept, who it is for, features, the look, and design no track owns
yet. The design of one track's area lives in that track's `design.md` (`.claude/docs/tracks/`),
under the same rules. How the product is built lives in `.claude/docs/tech/`.

## How docs here are written

- **The owner decides the design.** Every doc keeps three parts apart: Decided, Ideas and Open
  questions. Only the owner moves something into Decided, so propose it in your reply. Write ideas
  into a doc when the owner asks for it, not on your own.
- **Answers are leanings until the owner says "decided".** When the owner answers a list of open
  questions, or reacts to research, a mockup or concept art, write the answers under Ideas as the
  owner's leanings, with the date, and say so in the reply. A point moves into Decided only when
  the owner calls it decided.
- A decided point gets its date and a short reason next to it, in the same doc.
- One topic per file, named plainly, like `onboarding.md` or `pricing.md`. When a topic outgrows
  one file, give it a folder with its own `README.md` list.
- Add every new doc or folder to the list below in the same change. The guide check flags one that
  is missing.
